# Facet Proof 边缘像素的表达力分析：单值通道 vs. 覆盖信息

## 1. 信息在哪里被压扁：实现事实

渲染管线里，多表面信息只在一个点被丢弃：

**高采样层（信息完整，且持久保留）**
- `rasterize` 对每个亚像素存单一获胜者：`depth`（f64）、`ids`（u32）、`colors`（f32×3）（`facetproof/raster.py:17-19`）。共面 tie 时**较小 object_id 胜**（`raster.py:49-51`）。
- 分块协议把这三个通道**按亚像素**落盘：`depth.f64 / color.f32 / object.u32`（`facetproof/tile_protocol.py:14-17`）。分块提交后无任何删除路径（全仓无 `DELETE FROM facet_tiles`），备份也包含分块内容闭包（`tile_store.py:32-57`、`maintenance.py:282-295`）。**亚像素级身份分布在服务端数据根里其实是保留的。**

**下采样（唯一的减损点）**——`serialize_passes`（`facetproof/passes.py:15-31`）对每个输出像素：
- 颜色：4 个亚像素（`samples≤2`，`planner.py:15`）的**盒式平均**，混合一切贡献者（含背景）；
- 深度与 object id：**最近亚像素的单值**（`passes.py:19-24`，`min` 按 `(depth, offset)`，并列取扫描序最小者）；
- `covered_pixels`：`id != 0` 的像素计数（`passes.py:31`）。由于 `inf` 在 `min` 中必败，这等价于"**至少含一个前景亚像素**"的像素数，不是面积。

**消费方对单值语义的吸收**
- `pick` 返回该像素的单个 object 与深度（`plates.py:69-80`）——两者取自同一亚像素，自洽但只是"代表性样本"。
- `Comparisons` 读了 `object.u32` 却**从未使用**（`comparison.py:22`），变更检测只看颜色、深度有限性、深度差。
- `facetreader` 要求**恰好**六通道（`facetreader/archive.py:10-13,64`；`format.py:126`），`object.png` 必须是 id 的确定函数 `(id·(73,151,199))%255`（`format.py:170-172`，不携带新信息），`depth.png` 被解码但**不与 `depth.f32` 交叉校验**（`format.py:140-154`），`covered_pixels` 必须与 id 通道重算一致（`format.py:182-183`）。

## 2. 两种表达各自能支持什么判断

### 2.1 现有单值通道（facet-plate-1）能支持的判断

| 判断 | 依据 | 场景证据 |
|---|---|---|
| 点查询的**代表性**答案："该像素最近亚像素属于哪个零件、多远" | `plates.py:69-80`；id 与 depth 同源 | S1：50/50 边缘像素 `pick(1,0)` → `part-b`，depth 1.0 |
| **确定性**重放：同输入必得同字节 | tie 规则确定（`raster.py:49-51`、`passes.py:19`） | S4：三角形顺序对调，三通道字节完全相同 |
| 二值覆盖事实与计数："该像素至少一个亚像素是前景"；`covered_pixels` | `passes.py:31`；`format.py:182-183` | S3：仅 25% 前景的像素同样 id=1、计入 `covered_pixels=2` |
| 字节完整性与格式内一致性（hash、六通道、id↔预览、背景↔+∞ 深度） | `plates.py:54-67`；`format.py:126-183` | S7：真实 bundle 通过 `validate_bundle` |
| 颜色/轮廓/深度的**像素级**变更检测 | `comparison.py:23-33` | S6 的对照组 |

### 2.2 单值通道**不能**支持的判断（场景实证）

- **"该像素是否混合了多个零件"不可判定**。S5：像素 (1,0) 在场景 A（两个零件各 2 亚像素）与场景 B（一个零件、两种面色的两个面）下，`color.rgb`/`depth.f32`/`object.u32` **逐字节相同**。颜色平均对"零件间边缘""零件内面间边缘""前景/背景边缘"一视同仁——混色不是多零件的证据，单值 id 也不是单零件的证据。
- **少数派所有者不可见**。S2：part-b 只占 1/4 亚像素但最近 → 像素 id=2，`pick` 返回 part-b；像素颜色 (170,170,108) 的 3/4 来自 part-a，图版中 part-a 在该像素**无任何记录**。
- **覆盖比例不可得**。S1（50%）与 S2（25%）在图版里都是"id=2, depth=1.0"，无法区分。
- **共面接触的另一面被完全隐藏**。S4：共面两零件，tie 规则让 id=1 通吃，蓝色零件在颜色与 id 通道中零痕迹（`blue_visible_anywhere: false`）。
- **身份级变更不可检测**。S6：两图版仅 `object.u32` 不同（同像素 id 1↔2），`Comparisons` 报告 `color_changed=0, silhouette_changed=0, depth_changed=0`。
- **被完全遮挡的第三表面不可恢复**——这是光栅化本身的边界，加覆盖信息也救不回（见 §3 边界）。

### 2.3 增加覆盖信息能支持的判断

按表达力递增，可选形态：(a) 每像素主 id 的覆盖分数；(b) 每像素 `[(id, weight), …]` 列表；(c) 亚像素 id 位图（`samples≤2` → 每像素 4 个 u8/u32，对当前渲染器输出**无损**）。形态 (c) 严格包含 (a)(b)，以下按 (c) 评估：

1. **边缘分类**：纯像素 / 零件间混合 / 前景背景混合 / 共面接触（需配合深度相等性），S5 中 A、B 两场景立即可分（`{1:2, 2:2}` vs `{1:4}`）。
2. **面积加权统计**：`covered_pixels` 从"≥1 亚像素"升级为真实覆盖面积；S3 的 25% 像素不再与 100% 像素等权。
3. **拾取消歧**：`pick` 可返回排序候选集（S2：`part-a 75% / part-b 25%（最近）`），把"视觉多数"与"深度最近"分开陈述，而不是静默二选一。
4. **覆盖加权比对**：身份级变更（S6）与亚像素位移（权重渐变但最近 id 未变）都可度量；比对结论从"零变化"细化为"颜色未变、所有权转移 x 像素"。
5. **颜色-身份一致性解释**：混合色可由 `Σ wᵢ·cᵢ` 解释，审阅者能把紫色边缘像素归因于具体的两个零件，而不是无法核实的平均。

**边界（加了覆盖信息仍然不能做的）**：
- 覆盖分布是"**每个亚像素的赢家分布**"，不是深度层。S2 像素里 part-a 的深度、以及任何被完全遮挡的表面，仍然未知——除非同时提升深度通道（tile 层其实已有 f64 亚像素深度，但图版不含）。
- 共面 tie 的输家**在写入前就被丢弃**（`raster.py:50` 的 `continue`），下采样阶段无任何记录可恢复；要表达共面接触需改光栅化，而非改通道。
- 反推仍然单向：有覆盖信息可以**解释**颜色，不能从颜色**验证**覆盖（颜色是面级平着色的平均，多解）。

## 3. 更充分的边缘信息对历史图版的影响

**历史图版不可原地丰富。** 图版是内容寻址、hash 锁定的 `facet-plate-1`：`visual_hash` 覆盖全部通道描述符（`worker.py:39-44`），proof 记录引用 `visual_hash`（`proofs.py:15-16`），bundle 导出后即不可召回。任何"第七通道"都构成新格式版本，而非旧图版的增补：

- **旧读取器拒绝新图版**（实测 S7）：向合法 bundle 加入一个 `passes/coverage.f32` 成员，`facetreader` 立即以 `archive_members: "Unexpected archive member"` 拒绝——成员集合是**精确匹配**（`archive.py:64`），没有"忽略未知成员"的宽容路径。`facet-plate-2` 图版对现有 `facetreader` 一律无效，与损坏同态。
- **新读取器必须双态**：接受 v1 时，边缘像素的解释只能保持"代表性亚像素"语义，**不能回溯性声称混合比例**——v1 字节里根本没有这个信息（S5 证明连"是否混合"都不可判定）。v1 图版的 `picks`（含已导出 bundle 里固化的 `picks.json`）永远是单值事实。
- **重算路径存在但产物是新图版**：服务端 `facet-tile-1` 分块保留了亚像素 id/深度/颜色（且无 GC、备份含分块），历史曝光的边缘信息原则上可重算——但重算结果必须作为新图版登记（新 `visual_hash`、新 plate id），旧 proof 的接受状态不自动转移（`proofs.py:38-39` 只校验当下 payload）；`Comparisons` 要求同尺寸同 `lens_hash`（`comparison.py:17-18`），新旧版图版可以比，但比较语义横跨两种通道定义，结论需标注格式代际。
- **统计口径断裂**：`covered_pixels` 在 v1 是"≥1 亚像素前景"，若 v2 改为面积加权，同名指标跨图版不可比——`facetreader` 目前强制它与 id 通道重算一致（`format.py:182-183`），v2 必须换字段名而非改语义。

## 4. 结论边界

1. 从单值图版**不能**推出"该像素只含一个零件"（S5 字节级不可区分），也**不能**推出"混合像素的另一成分是谁"（S2）。
2. `covered_pixels` 不是面积估计，是"含前景亚像素的像素数"（S3）。
3. 颜色混合**不能**反推多零件：面间边缘、背景边缘产生同样的平均（`passes.py:26` 的无差别盒式滤波）。
4. 比对结果为零**不排除**身份级变更（S6，`object.u32` 未参与比对）。
5. 即使加上覆盖信息：被完全遮挡的表面、共面 tie 的输家、非赢家亚像素的深度，依然不可知——这些需要深度层或光栅化改动，超出"通道表达"范畴。
6. `depth.png` 当前不与 `depth.f32` 交叉校验（`format.py:140-154`），单值表达的实际保证比"六通道齐备"看起来更窄：深度只有原始通道受 hash 保护，预览图不受一致性约束。
